# 药材价格品级分组设计

## 背景

“药材上限价”页面当前只接收扁平的“药材名 → 价格”对象，导致原始 YAML 中的品级信息在 WebUI 中丢失。页面生成的药材行使用 `.herb-row`，现有 CSS 却只匹配 `#herb-list .field`，因此行布局样式没有生效，长列表显示混乱。

本次修改只调整药材品级数据的读写方式和 WebUI 展示，不采用需求示例中的价格值，也不改变炼丹、购买药材时的价格判断逻辑。

## 目标

- 在 WebUI 中按九品至一品固定顺序展示药材。
- 使用折叠分组控制长列表长度，并显示每组药材数量。
- 每行提供品级下拉框，可在一品至九品之间移动药材。
- 保存后在 YAML 中保留品级嵌套结构。
- 兼容旧页面保存出的扁平 YAML。
- 保留当前实际配置中的药材价格。

## 非目标

- 不调整任何药材价格。
- 不改变坊市扫描、动态购买、利润计算或炼丹流程。
- 不增加药材搜索、批量改价、导入导出等附加功能。
- 不重新设计配置中心的其他页面。

## 方案选择

采用“折叠品级分组”方案。

未采用的方案：

- 全部展开分组：品级清楚，但药材数量较多时页面过长，移动端滚动成本高。
- 单表格加品级列：编辑集中，但视觉上仍是扁平长列表，不能解决品级层次不清的问题。

## 数据模型

### 品级定义

系统使用以下固定品级，显示顺序不可由数据输入改变：

1. 九品药材
2. 八品药材
3. 七品药材
4. 六品药材
5. 五品药材
6. 四品药材
7. 三品药材
8. 二品药材
9. 一品药材

Web API 使用嵌套对象表达分组：

```json
{
  "groups": {
    "九品药材": {
      "尘磊岩麟果": 1000.0,
      "离火梧桐芝": 1000.0
    },
    "八品药材": {}
  }
}
```

页面提交保存时使用相同结构。空品级可以保留在 API 响应中，但持久化 YAML 时可以省略空映射；重新加载后页面仍补齐并显示全部九个品级。

### 运行时兼容

自动购买和炼丹逻辑继续使用现有的扁平 `herb_max_prices` 映射。优化器加载分组数据后，同时生成：

- 分组映射：用于 WebUI 展示和嵌套 YAML 持久化。
- 扁平映射：用于现有购买价格查询。

保存分组数据时，先校验并规范化药材名和价格，再更新上述两种表示，避免改变现有业务调用方。

### 旧扁平配置迁移

加载旧扁平 YAML 时：

- 已存在于仓库默认药材目录中的名称，按默认目录品级归类，但价格取账号当前文件中的值。
- 无法从默认目录识别品级的自定义药材进入“待分类”集合。
- “待分类”只作为页面迁移状态，不是合法持久化品级；用户必须为这些行选择一品至九品后才能保存。

该迁移不会自动重写文件，只有用户主动保存页面时才写入新的嵌套格式。

## WebUI 交互

### 分组

- 页面按九品至一品显示九个折叠标题。
- 标题包含品级名称、当前药材数量和展开/收起图标。
- 默认只展开第一个非空品级；若全部为空，则默认展开九品。
- 空品级仍显示，数量为 0。
- 同一时间允许用户展开多个品级。

### 药材行

每行固定包含：

- 品级下拉框：选项为九品至一品。
- 药材名称输入框。
- 价格输入框，单位保持“万灵石”。
- 图标式删除按钮，并提供可访问名称或悬停提示。

用户修改品级后，该行立即移动到目标品级，并自动展开目标分组。新增药材默认使用当前最近展开的品级；没有可判断的当前分组时使用九品。

### 保存校验

保存前检查全部行：

- 品级必须为一品至九品之一。
- 药材名去除首尾空白后不能为空。
- 价格必须为大于 0 的有限数值。
- 规范化后的药材名在所有品级中必须唯一。

存在错误时不发送保存请求，在对应行显示错误状态，并通过现有 toast 告知原因。通过校验后才提交分组对象。

### 响应式布局

- 桌面端使用稳定网格列，品级、名称、价格和删除操作不会因内容变化而挤压错位。
- 窄屏下允许控件换行，药材名称占主宽度，价格和删除操作保持可点击。
- 分组标题和行控件不使用随视口变化的字体尺寸。

## API 与持久化

### 加载接口

`herb_prices/load` 返回账号当前分组数据和待分类数据，并继续保留现有 `prices` 扁平字段以兼容旧调用方；新页面只消费 `groups` 和 `unclassified`。

### 保存接口

`herb_prices/save` 接收 `groups`。后端不信任前端校验，会再次验证品级、药材名唯一性和正价格；无效请求返回 400，不修改内存和文件。

验证通过后，优化器以嵌套结构写入账号对应的 `herb_max_prices.yaml`，并同步更新运行时扁平价格映射，使新价格无需重启即可生效。

## 错误处理

- YAML 不存在或为空：返回九个空分组，页面允许新增药材。
- YAML 无法解析：沿用现有日志告警，API 返回可识别的加载失败，不以空数据覆盖原文件。
- 保存验证失败：返回 400 和明确原因，页面保留用户输入。
- 文件写入失败：保持原有内存映射不变，返回 500，避免出现内存已生效但磁盘未保存的不一致状态。
- 网络请求失败：沿用配置页现有错误提示和按钮恢复逻辑。

## 测试策略

后端测试覆盖：

- 嵌套 YAML 加载后同时生成正确的分组和扁平映射。
- 嵌套保存后 YAML 保留品级结构，运行时扁平映射同步更新。
- 旧扁平配置中的已知药材按目录归类并保留账号价格。
- 旧扁平配置中的未知药材进入待分类集合。
- 非法品级、重复名称、空名称和非正价格被拒绝，且不修改已有状态或文件。
- 加载和保存接口始终使用当前选择账号的数据文件。

前端测试覆盖：

- 九个品级按九品至一品生成。
- 默认展开第一个非空品级，空数据时展开九品。
- 修改下拉框会把药材行移动到目标品级。
- 新增行默认归属最近展开的品级。
- 保存序列化为嵌套分组对象。
- 重复名称、待分类项和无效价格阻止提交。

完成实现后运行项目现有完整测试集，并对配置页面进行桌面与窄屏视觉检查。

## 验收标准

- 药材列表不再以未分组长列表显示。
- 九品至一品均有清晰、可折叠的分组标题和数量。
- 每行可选择一品至九品，切换后立即移动到对应分组。
- 当前配置价格在首次加载和迁移过程中保持不变。
- 保存后账号 YAML 为品级嵌套结构，重新加载分组不丢失。
- 现有自动购买与炼丹价格判断测试保持通过。
- 桌面和窄屏页面无控件重叠或文本溢出。
