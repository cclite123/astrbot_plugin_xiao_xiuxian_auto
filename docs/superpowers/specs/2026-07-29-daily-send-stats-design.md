# 每日发送统计设计

## 背景

自动炼丹会持续发送坊市查看、坊市购买和炼丹配方命令，但当前没有按账号统计这些命令的当日发送量。WebUI 只能看到绑定会话数，无法判断当天的自动化负载。

## 目标

- 按北京时间自然日统计三类官方命令：坊市查看、购买、炼丹。
- 统计当前账号所有绑定群的合计次数，不混入其他账号。
- 数据持久化，插件重启后保留当天计数，跨日自动归零。
- 在 WebUI 新增独立“发送统计”页签，显示三项次数与合计。

## 统计口径

命令成功进入官方命令发送队列时计数，而不是等到底层 OneBot 返回成功后计数。因此：

- 被验证码暂停、仍留在队列中的命令计入统计。
- 同一队列项恢复后真正发送时不重复计数。
- 后续底层发送失败不会撤销已经产生的入队计数。
- 空消息、非官方消息和没有进入队列的延迟活动命令不计数。

分类前移除开头的官方机器人 `@QQ` 和空白，再按命令前缀判断：

- `坊市查看` → `market_view`
- `坊市购买` → `purchase`
- `配方主药` → `alchemy`

其他命令不计入本功能。

## 后端结构

新增 `send_stats.py`，提供 `DailySendStats`：

- `classify(text)`：返回三种类别之一或空值。
- `record(self_id, text)`：在异步锁内读取当天记录、执行跨日重置并递增匹配类别。
- `snapshot(self_id)`：返回当前账号当天三类计数与合计；跨日读取返回零值并更新存储日期。

存储复用现有 `JsonStore`，使用单独键保存当前日期和账号映射：

```json
{
  "date": "2026-07-29",
  "accounts": {
    "123456789": {
      "market_view": 128,
      "purchase": 342,
      "alchemy": 76
    }
  }
}
```

所有日期通过 `Asia/Shanghai` 计算。异步锁覆盖读取、递增和写回，避免多个群并发发送导致丢计数。

`XiaoXiuxianAuto` 初始化一个共享统计器。`_enqueue_official_command` 在把命令追加到队列后调用统计器；统计写入失败只记录告警，不撤回已排队命令。

## Web API 与界面

新增账号级 POST 接口 `send_stats/load`：

```json
{
  "self_id": "123456789",
  "date": "2026-07-29",
  "counts": {
    "market_view": 128,
    "purchase": 342,
    "alchemy": 76
  },
  "total": 546
}
```

接口复用现有账号校验，禁止读取未配置或未绑定账号的数据。

WebUI 新增特殊页签“发送统计”：

- 显示北京时间日期、坊市查看、购买、炼丹和三项合计。
- 打开页签时立即加载，每 5 秒自动刷新。
- 提供手动刷新按钮；刷新失败时保留最近一次成功数据并显示错误提示。
- 切换账号时保持当前页签，并加载新账号数据。
- 离开发送统计页签时清理定时器，避免后台重复请求。
- 桌面端三列显示，窄屏改为单列，不出现横向溢出。

## 错误处理

- 存储不存在或内容不是对象：按当天零值初始化。
- 存储日期不是当天：原子替换为当天空记录。
- 旧数据中的负数、非数字或未知字段：读取时规范为零或忽略。
- API 加载失败：返回明确错误；WebUI 不清空已显示的成功快照。
- 统计写入异常：记录警告，发送队列继续运行。

## 测试与验收

后端测试覆盖命令分类、非目标命令忽略、验证码暂停时入队计数、并发递增、账号隔离、重启读取和跨日归零。

API 与前端测试覆盖账号校验、返回结构、特殊页签接入、5 秒刷新、离开页签清理定时器和响应式样式。

验收时确认：三个数值只随对应命令入队增长；验证码暂停时仍增长；恢复发送不重复；切换账号数据隔离；跨日显示零值。
